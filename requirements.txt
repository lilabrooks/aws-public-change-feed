# Pinned runtime dependencies for the deployed packages.
#
# ADR-006 requires pinned production dependencies and reproducible build
# artifacts. The matching and corpus-evaluation code is deliberately
# dependency-free: it reads normalized JSON and the release configuration,
# both of which the standard library handles. Feed acquisition, DynamoDB
# state, and Slack delivery will add entries here as those milestones land.
#
# Release publication is the first entry. `releases.py` imports
# `botocore.exceptions` to translate S3 error codes into the outcomes ADR-019
# distinguishes; the S3 client itself is injected, so the package never calls
# `boto3.client` on its own. `boto3` is pinned rather than `botocore` because
# every caller constructing that client needs it and boto3 pins a compatible
# botocore in turn.
boto3==1.43.83
#
# The release loader parses `config.yaml` at runtime, so PyYAML joins it. The
# audit that added the boto3 pin found that entry missing because the adapter
# imported botocore lazily; this one is a module-level import in `loading.py`
# and is declared with the code that needs it.
PyYAML==6.0.3
# Runtime release loading validates the fetched document bodies against the
# same owned schemas used before publication. Pointer metadata alone cannot
# make incompatible or extended document bytes safe to evaluate.
jsonschema==4.26.0
